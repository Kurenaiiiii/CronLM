**A tiny transformer, trained from scratch, that translates plain-English scheduling phrases into cron expressions — verified bit-exact against llama.cpp's GGUF export.**

> *"every weekday at 9:30am" → `30 9 * * 1-5`  
> "first of every month at midnight" → `0 0 1 * *`  
> "every 15 minutes between 9am and 5pm" → `*/15 9-17 * * *`*

CronLM is a 4.8-million-parameter character-level GPT that learns a deterministic language from synthetic data generated by a grammar engine. Everything — the labels, the split, the model class, the evaluation — is built locally, end to end. There is nothing to download except the code.

## Results

Measured on a fixed test set of 100,000 phrases (byte-identical splits; seed 1337):

| Model | Params | Training | Test | Combo holdout | Paraphrase holdout | Golden | Validity |
|---|---|---|---|---|---|---|---|
| `small` (pregenerated, stopped early at 48k steps) | 4.8M | 132.3 min on 1×T4, fp16 | **99.999%** | 90.68% | 88.97% | 96.50% | 100% |
| **`small_online`** (fresh examples every step) | 4.8M | ~68k steps on 1×T4, fp16 | **100.00%** | **93.48%** | **90.25%** | **97.00%** | 100% |

- **test** = same distribution as training, unseen phrases. Both models solve it; `small_online` hits 0 failures in 100k examples.
- **combo holdout** = exact-time `hour:minute` pairs reserved by hash, never seen in training — measures rule-learning, not memorization.
- **paraphrase holdout** = 38 reserved template families never shown to the model. Brittleness is intentional and reported, not hidden.
- **golden** = 200 hand-written, hand-verified pairs covering every clause kind.

The `small_online` checkpoint is the primary artifact; its GGUF is at `exports/cronlm-small-online-f32.gguf` and was verified to match the PyTorch model on 150/150 validation prompts.

## What's inside

- **Grammar-labeled synthetic data engine** (`grammar.py`) — builds a structured spec first, renders both the English phrase and the canonical cron from it. Labels are correct by construction; the model never has to infer a cron from a sentence heuristically.
- **Hand-written decoder-only GPT** (`model.py`, ~150 lines) — learned absolute positional embeddings, pre-LayerNorm blocks, causal attention via `scaled_dot_product_attention` (explicit `softmax(QK^T/√d)V` shown in comments), GELU MLP (4×), tied output head, 1/√(2L) scaled init on residual projections.
- **Tokenizer** (`tokenizer.py`) — character-level, 48 tokens, `vocab.json` saved with every checkpoint so inference never depends on code state.
- **Two training modes**: pregenerated (fast, for dev) and `--online` (fresh random example per step; train never repeats; val/test stay fixed on disk). Online mode produced the best model.
- **Evaluation that actually catches things**: exact/semantic match, validity rate, per-level and per-field accuracy, per-template dumps, and a failure JSONL for error analysis. See `docs/DIAGNOSTIC.md` for a worked 1,864-failure taxonomy that pinpointed reserved-template blowups and minute-45 collapse.
- **GGUF export** (`exports/`, `scripts/gguf/`, `export_gguf.py`) — verified bit-exact against the PyTorch model on 150/150 greedy predictions. The GPT-2-family export carries a deliberately dead `\x7f \x7f` merge because llama.cpp requires a non-empty merges list and GGUF forbids empty ones. Usage is shown below.

## Quick start

Requirements: Python 3.9+, `pip install -e ".[dev]"`, a CUDA GPU or patience.

```bash
git clone https://github.com/Kurenaiiiii/cronlm.git && cd cronlm
python -m venv .venv && source .venv/bin/activate
pip install torch && pip install -e ".[dev]"
pytest -q
python -m cronlm.cli gen-data --out data --train 500000 --val 20000 --test 100000 --seed 1337
python -m cronlm.cli train --config configs/small_online.yaml --device cuda --amp fp16 --online
```

Talk to it in one line:

```bash
llama-completion -m exports/cronlm-small-online-f32.gguf -p "every weekday at 9am<sep>" --temp 0 -c 160
# -> every weekday at 9am0 9 * * 1-5 [end of text]
```

Or train the smaller `tiny` model locally on a GTX 1650 (~0.8M params, fp32, ~15 minutes to a usable checkpoint). On a laptop with a 4 GB card, training `small` from scratch will OOM in fp32; use Kaggle or fp16 — see `kaggle_train_online.ipynb`, which produced the 93.48% combo result end to end from a fresh clone with **no downloaded weights**.

## Design decisions worth pointing at

- **Labels are correct by construction.** The generator composes a structured spec first, then renders the phrase from templates and the cron string from the spec — the cron is never parsed out of the phrase. The one failure mode this eliminates is the hardest one: the model cannot learn from wrong labels because there aren't any.
- **Hash-based split, never sequential.** md5 of every phrase mods into 1000 buckets; 0–39 val, 40–239 test, 240–999 train. A phrase can never leak across splits, and the split is stable under regeneration. Online mode filters through the identical gate.
- **Combo holdout for memorization.** 63 `(hour, minute)` pairs (~4.4% of 1,440) are reserved and never shown to the model. That exposes whether it learned the *rules of time* or memorized pair-wise mappings — the price for that honesty is a visibly lower combo score (93.48%), which is reported as-is.
- **Exact/semantic/validity, not perplexity.** A 100%-perplexity model is irrelevant if it emits invalid cron. Every metric here catches a distinct, actionable failure class.
- **Determinism everywhere.** Seeds flow through torch, Python `random`, NumPy, and the hash split. `gen-data` is byte-reproducible (tested).

## Testing

`pytest -q` → **79 passed in ~12 min.** Coverage includes cron canonicalization, validation (incl. dom/dow restriction rules), next-run scheduling on known dates, 50k generated pair validation, reserved-template leak checks for `--online`, tokenizer round-trip + unknown-char errors, model shape/causality/padding/param-count/32-example overfit, golden set validation, byte-level gen-data determinism, and end-to-end `--smoke` training + resume + predict.

## Honest limits

- 100% means 100% on this grammar's distribution, not free-form English.
- The combo-holdout gap is structural, not a bug: ~34.7% of combo rows use never-trained reserved templates; failure clusters by the same templates (see `docs/DIAGNOSTIC.md`).
- The paraphrase holdout exists so brittleness is measured, not hidden.
- Steps in `*/N` start at the field minimum (minute 0, hour 0, month 1) — cron semantics are authoritative.
- No 6/7-field cron, no macros, no L/W/#, no dom+dow restriction.
